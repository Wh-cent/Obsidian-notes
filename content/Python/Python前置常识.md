## 计算机底层最小可寻址存储单位：字节Byte

- 由于一个字节就是八个bit{比特}，可以理解为，字节就是一节单位
- 特殊的是，这一节单位共八个0/1，这样，八位二进制一共可保存256种可能性{即0-255的数字}
- 1KB = 1024B；后续1MB、1GB、1TB也都是1024倍的转换


## 精度丢失「有多种类别」

- **浮点数误差**：按照标准，python是用二进制方式保存数字的，而对于小数，只能做到尽可能的拟合，而做不到完全相同于是会出现：print(0.1+0.2)，结果却是：0.30000000000000004
- 所以在用浮点数判断是否相等时，或许会出错，即：0.2+0.1=0.3返回False  
    「参考：IEEE 754·浮点数标准，该标准仍未浏览，仅做提示」

## 原码、反码、补码「三种表示方式」

- 看了AI解释，颇为复杂，总之，这是为了解决负数计算而演变的表示形式
- 原码：sign-magnitude / 反码：ones' complement / 补码：two's complement —— 不清楚为何这样命名
- 其中，正整数的原码、反码、补码就是该正整数二进制表示；负整数的原码是其对应正整数二进制前提下，八位二进制最左边的补零改为一；负整数的反码是该负整数原码的取反；负整数的补码是该负整数原码的取反再加一
- 由于原码和反码在计算中仍然较为复杂，计算机领域最后仍采用补码的形式去计算负数类型的东西；在AI解释当中，该补码有一种退位轮换的感觉：对于3-5=-2这个式子，以时钟为认知模型，在3点往回退5个小时，其本身并不会显示-2点，而是10点，那么这种情况-2和10形成对应关系，对于计算3-2来说，即对应3+10=13，由于13超出12，同理进行轮换对应改成1，在结果上与3-2是一致的「这就令我非常震惊，为什么这种算法是合理的呢？莫名其妙的那种转换对应就能使结果保持一致，核心逻辑是什么？」

## 哈希函数「字典哈希，不包括密码哈希」

- hash，英文感知义为：切碎、弄乱
- 对于数据处理，相当于把各种类型的输入打乱，统一为固定长度的输出；有：hash function / value / table
- 依旧不理解其原理，总之是为了更好的定位，不用枚举式的在字典里一个个翻找；对给定的「键」，计算其哈希值，根据这个值以及相关原理，直接对应到字典某个位置，获得键值


## UTF-8编码，文件格式，文件后缀

UTF-8：一种针对文字的编码类型，同理有针对图像等不同内容的编码

文件后缀：只提醒操作系统可以用哪一种程序打开该文件，不改变文件内容本身；有些操作系统甚至可以先判断文件格式与后缀是否对应，再选择打开程序

文件格式：文件格式，是规定文件中的数据怎样组织、每部分代表什么、程序应该怎样读取的一套规则。二进制字节是按照这些规则保存下来的具体结果「如JSON样式的组织方式，可以理解为：内容具有一定的核心，而核心内容通过不同的字符，逻辑与范式进行联系，形成一套被扩展的展示信息」

### 编码理解

编码是一套表示规则，解码是按规则解释数据。要可靠地还原原文，需要使用匹配的规则；不同规则可能局部兼容，但不能因此随意混用

编码就像加密一样，应用规则进行转换，再按照对应规则还原
